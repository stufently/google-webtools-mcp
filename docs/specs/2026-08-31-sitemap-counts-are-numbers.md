# Счётчики sitemap — числа, а не строки

## Зачем, и это не теория

Search Console API отдаёт `warnings` и `errors` у карты сайта СТРОКАМИ:
в ответе лежит `"0"`, а не `0`. Наш тип это честно повторяет
(`src/api/types.ts`: `warnings?: string; errors?: string`), а весь код,
который эти поля читает, проверяет их на истинность — а строка `"0"`
в JavaScript истинна.

Отсюда наблюдаемый на живом сайте бред: отчёт по `thaigid.top` печатает
одновременно

    | **Status** | Error |
    | **Errors** | 0 |
    | **Warnings** | 0 |

и добавляет рекомендации «This sitemap has errors: 0» и «Check the sitemap
file for XML syntax errors». Карта при этом исправна: `HTTP 200`, валидный
XML, ровно 5715 адресов, скачана Google без единой жалобы.

Ошибка повторена в коде примерно десять раз, поэтому лечить надо не строку,
а границу: привести счётчики к числу при разборе ответа API и всюду сравнивать
их с нулём.

## Что сделать

### 1. `src/api/types.ts`

В `interface SitemapInfo` сменить тип обоих полей:

    warnings?: number;
    errors?: number;

### 2. `src/api/sitemaps.ts`, функция `toSitemapInfo`

Сейчас:

    warnings: raw.warnings ?? undefined,
    errors: raw.errors ?? undefined,

Сделать разбор в число на этой границе и только здесь. Требования к разбору:

* `"0"` → `0`; `"3"` → `3`; `3` → `3`;
* `null`, `undefined`, пустая строка и всё, что не разбирается в конечное
  число, → `undefined`;
* отрицательных значений API не отдаёт, специально их не обрабатывать.

Разбор вынести в маленькую функцию рядом с `toSitemapInfo` (например
`toCount`), чтобы `submitted`/`indexed` можно было починить тем же способом
позже, но САМИ `submitted`/`indexed` в этой задаче НЕ трогать: их читают
другие места, и это отдельная работа.

### 3. Все читатели полей

Заменить проверку на истинность проверкой «больше нуля». Места известны
(проверено `grep`), список полный:

* `src/tools/sitemaps/index.ts` — строки с `sm.errors ? 'Error' : 'Success'`
  (их ДВЕ), `sitemaps.filter((s) => s.errors).length`, и четыре ветки
  `if (sm.warnings)` / `if (sm.errors)`, печатающие строки таблицы
  и рекомендации.
* `src/tools/reports/index.ts` — `filter((s) => s.errors)`,
  `filter((s) => s.warnings)` во всех местах, где они встречаются
  (их несколько, найди все).

Правило замены одно: `s.errors` как условие → `(s.errors ?? 0) > 0`,
то же для `warnings`. Там, где значение ПЕЧАТАЕТСЯ, оно остаётся значением.

Строка статуса должна стать:

    const status = sm.isPending ? 'Pending' : ((sm.errors ?? 0) > 0 ? 'Error' : 'Success');

### 4. Проверка на живом ответе

После правки статус карты `https://thaigid.top/sitemap.xml` обязан стать
`Success`, а не `Error`. Проверять вызовом API ты не сможешь (учётные данные
недоступны из прогона) — поэтому вместо этого напиши модульный тест
на `toSitemapInfo` с ровно тем ответом, который API отдаёт на самом деле:

    { path: 'https://thaigid.top/sitemap.xml', isPending: false,
      isSitemapsIndex: false, type: 'sitemap',
      lastSubmitted: '2026-08-30T12:37:37.507Z',
      lastDownloaded: '2026-08-30T12:37:38.082Z',
      warnings: '0', errors: '0',
      contents: [{ type: 'web', submitted: '5715', indexed: '0' }] }

## Не трогать

* Поля `submitted` и `indexed` у `SitemapContent` — их тип остаётся `string`.
* Любые другие модули: `search-analytics`, `url-inspection`, `ga4-*`,
  `verification`, кеш, rate limiter, обработку ошибок.
* `package.json` (в том числе версию), `Dockerfile`, `docker-compose.yml`,
  `tsup.config.*`, `tsconfig.json`.
* Каталог `dist/` — он собирается сборкой, руками его не править.
* Существующие 183 теста: они обязаны продолжать проходить без правок.

## Критерии приёмки

Проверяемые утверждения. Новые тесты класть в `tests/unit/sitemaps.test.ts`
(файла нет — создать), стиль брать у соседних файлов в `tests/unit/`.

1. `toSitemapInfo` на ответе с `errors: '0', warnings: '0'` даёт
   `errors === 0` и `warnings === 0` (именно числа, не строки).
2. `toSitemapInfo` на ответе с `errors: '3'` даёт `errors === 3`.
3. `toSitemapInfo` на ответе без полей даёт `errors === undefined`
   и `warnings === undefined`.
4. Форматирование карты с нулевыми счётчиками даёт статус `Success`
   и НЕ печатает ни строку `| **Errors** |`, ни рекомендацию про ошибки.
   (Если формат вывода лежит в функции, которую можно позвать из теста, —
   проверить её; если он размазан по обработчику инструмента, достаточно
   проверить само выражение статуса, вынеся его в маленькую именованную
   функцию рядом.)
5. Карта с `errors: '3'` по-прежнему даёт статус `Error` и печатает `3`.
6. `node_modules/.bin/tsc --noEmit` проходит без ошибок типов.
7. `node_modules/.bin/vitest run` — все тесты зелёные, число тестов
   не меньше прежних 183.

## Разрешения

Спросить у человека ты не сможешь — режим неинтерактивный. Поэтому заранее:

* Правь перечисленные файлы без подтверждения.
* Создавай новые файлы тестов в `tests/unit/` без подтверждения.
* Запускать проверки МОЖНО и НУЖНО, ровно этими командами, из корня репозитория:

      node_modules/.bin/vitest run
      node_modules/.bin/tsc --noEmit

  Оба бинаря на месте, всё уже установлено.
* **НЕ запускай `npm install`, `npm ci`, `npm update`, `pnpm`, `yarn`** —
  ничего, что ставит или обновляет пакеты. `node_modules` уже собран,
  и трогать его нельзя.
* НЕ запускай `npm run build` и `tsup`: `dist/` собирает человек при выкладке.
* НЕ делай коммитов, НЕ переключай ветки, НЕ трогай `git`.
* Node на хосте — v24, в образе `node:20-slim`. Код обязан оставаться
  совместимым с обоими; ничего специфичного для новых версий не вводи.
